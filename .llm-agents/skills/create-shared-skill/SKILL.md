# 共有スキルの作成・更新

どのエージェントで実行しても、同じ共有ディレクトリにスキルの本体を作成し、共通の一覧に登録する。

## 配置と参照

- 対象リポジトリの `AGENTS.md` と `.llm-agents/instructions.md` を適用する。以降のリポジトリ内パスはそのルートを基準とする。
- 本体は `.llm-agents/skills/<skill-name>/SKILL.md` の1か所に置く。エージェント別ディレクトリやユーザのホームに本文を複製しない。
- 一覧は `.llm-agents/README.md` の「共有スキル一覧」に集約する。コマンド登録は `.llm-agents/scripts/register-skills.py` で行い、`.claude/skills/<名前>` と `.agents/skills/<名前>` から本体への相対シンボリックリンクを作る。Copilot は `.claude/skills/` も探索するため、専用のコピーを作らない。

## 作成手順

1. 依頼から、スキルの目的、利用する場面、必要な入力、期待する成果物を把握する。実装に必要な情報が不足する場合だけ確認する。
2. 一覧と既存の対象スキルを確認する。同じ目的のスキルがある場合は更新を検討し、無関係なスキルやユーザの変更を上書きしない。
3. 名前は小文字の英数字とハイフンを使い、64文字未満とする。先頭・末尾のハイフン、連続するハイフン、パス区切りは使わない。ディレクトリ名と frontmatter の `name` を一致させる。
4. 下記の形式で `SKILL.md` を作成する。説明と本文は日本語にし、例示用の値を実際の依頼内容に置き換える。
5. 必要な場合だけ `scripts/`、`references/`、`assets/` を追加する。補助ファイルへの参照はスキルのディレクトリを基準に記載し、いつ読む・実行するかを本文に書く。
6. 「共有スキル一覧」に名前、利用する場面、本体への相対リンクを追加または更新する。別の一覧やエージェント別の説明を作らない。
7. リポジトリのルートで `python3 .llm-agents/scripts/register-skills.py` を実行し、新しいスキルを登録する。Windows の Python ランチャーでは `python3` を `py -3` に置き換える。既存ファイルとの衝突は上書きで解決しない。
8. 下記の確認を行い、作成した本体へのリンク、呼び出し例、確認結果を報告する。
9. `.llm-agents/README.md` の「共有スキル一覧」に新しいスキルが正しく追加されていることを確認する。

## SKILL.md の形式

frontmatter は3エージェントで共有しやすい `name` と `description` を基本とする。`description` には能力と利用する場面を具体的に書き、無関係な依頼まで対象にしない。

```markdown
---
name: review-changes
description: 作業中の差分をレビューし、不具合と検証漏れを報告する。コミット前の変更レビューを依頼されたときに使う。
---

# 変更のレビュー

## 入力と成果物

対象の差分を入力とし、根拠となるファイル位置と影響を添えた指摘を返す。

## 手順

1. 指定された差分と関連コードを確認する。
2. 不具合、互換性、検証漏れを調べる。
3. 重要度順に指摘と根拠を報告する。修正を依頼されていない場合はレビュー結果を返す。

## 確認

指摘が実際の差分に対応することを確認し、推測と確認済みの事実を区別する。
```

見出しや手順の数は用途に合わせる。既に共通プロンプトにあるルールや一般的な説明を繰り返さず、その作業に固有の判断基準を書く。

## エージェント間の互換性

- 特定製品の専用ツール名、スラッシュコマンド、プラグインを実行の必須条件にしない。ファイルの読み書きやターミナルなど、必要な能力で手順を記述する。
- 外部サービスなど固有の依存が必要な場合は依存を明記する。利用できない環境では代替手順を示すか、不足している能力を報告する。共有できることと、依存ツールが利用できることを区別する。
- 補助スクリプトは可能な範囲で標準ライブラリを使う。OS 固有の操作が必要なら、対応 OS と Dev Container での実行方法を記載する。
- 作成したスキルに、依頼範囲を超える操作権限や承認を省略する指示を付け加えない。

## 確認

- frontmatter の `name` と `description` が空でなく、名前とディレクトリ名が一致している。
- 本文が完成しており、雛形の未記入項目や利用できないローカル絶対パスを含まない。
- 一覧のリンクと、本文で参照する補助ファイルが存在する。
- 想定する依頼を1つ当てはめ、入力から成果物までの手順に不足がないか確認する。
- スクリプトを追加・変更した場合は、一時ディレクトリで代表的な入力を使って実行確認する。検証が依頼範囲を超える操作を伴う場合は実行せず、その制約を報告する。
- 共通プロンプトから一覧、本体まで辿れることを確認する。実際に起動していないエージェントでの動作を「検証済み」と報告しない。
- `python3 .llm-agents/scripts/register-skills.py --check` で登録を確認する。リンクの作成権限がない場合は未登録として報告し、本文のコピーで代替しない。

呼び出し例にはエージェントごとの記法を示す。Claude Code と GitHub Copilot（VS Code）は `/review-changes`、Codex（CLI・IDE）は `$review-changes` を使う。スキルが候補に出ない場合は、エージェントの再起動または VS Code のウィンドウ再読み込みを案内する。

共通の文章による呼び出しも利用できる。

```text
このリポジトリの review-changes スキルを使って、現在の差分をレビューしてください。
```

名前で読み込まれない場合の例も示す。

```text
.llm-agents/skills/review-changes/SKILL.md を読み、その手順で現在の差分をレビューしてください。
```
